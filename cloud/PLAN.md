# Облачная версия Codary Code: план и оценка ресурсов

Состояние на 22.10.2026. Прототип работает на сервере Netcup (Германия) и изолирован: пользователей у него нет, вход возможен только по токену,
который подписывает сайт (черновик `cloud/php/code-cloud.php` на сайт не выложен).

## Что это

Открываете сайт, входите в личный кабинет codary.ru и попадаете в то же приложение Codary Code, но в браузере. Агент работает не на вашем компьютере,
а в **отдельном контейнере на нашем сервере**: свои файлы, свой терминал, свои ключи нейросетей (вы подключаете их сами, как в приложении).
Собственной модели нет; облачная версия просто даёт рабочую среду без установки (и с выходом к зарубежным API из Германии, чего не даёт российский IP).

## Как устроено

```
браузер ── https ──> nginx ── auth_request ──> менеджер (FastAPI, 127.0.0.1:8200)
                       │                         • /enter: проверка подписанного токена сайта, cookie на 12 часов
                       │                         • /auth: кто это, есть ли его контейнер, куда направить
                       │                         • запуск/остановка контейнеров, засыпание по простою
                       └── proxy (HTTP, потоки, WebSocket) ──> контейнер пользователя (сервер OpenCode с брендингом Codary,
                                                              встроенный веб-интерфейс, плагин расписания и Telegram)
```

* **Вход.** Сайт выдаёт одноразовый токен (HMAC-подпись общим секретом, срок до 5 минут) и отправляет на `/enter`. Кто имеет право входить, решает сайт
  (список допущенных, позже платный доступ); менеджер доверяет только подписи.
* **Среда.** Образ `codary-cloud/workspace` (1,33 ГБ, один на всех): наш сервер OpenCode одним бинарником с веб-интерфейсом, git, ripgrep, python, Node.
  На человека — контейнер `cc-u<id>` и два тома: домашняя папка (настройки, ключи, сеансы) и `/workspace` (проекты). Тома переживают остановку.
* **Засыпание.** Нет запросов 20 минут и агент не занят — контейнер останавливается, тома остаются. Следующий вход поднимает его за секунды.
* **Ёмкость.** Предел одновременных сред задаётся настройкой (сейчас 3); сверх предела пользователь видит страницу «Все места заняты» с автообновлением.

## Защита (что уже сделано в прототипе)

| Угроза | Мера | Проверено |
| --- | --- | --- |
| Чужой заходит без прав | подпись токена, срок, одноразовость, cookie HttpOnly+Secure | да (7 проверок) |
| Один пользователь лезет к другому | отдельные контейнеры и тома, связь между контейнерами выключена | да |
| Выход на сервер и соседние службы | правила сети: контейнеры не ходят на сам хост, в частные сети, в `169.254.*` (метаданные), на SMTP | да (изнутри контейнера) |
| Захват ресурсов | лимит 1 ГБ памяти (без свопа), 1 процессор, 512 процессов, `cap-drop ALL`, `no-new-privileges`, не root | да |
| Забытые простаивающие среды | засыпание по простою | да |

## Замеры (22.10.2026)

Сервер: 4 vCPU AMD EPYC Genoa, 8 ГБ памяти + 8 ГБ подкачки, диск 251 ГБ (свободно ~200 ГБ). На нём уже живут другие службы Антона
(агент-платформа, обработка фото, подготовка видео, поиск): занято 1,7–3,4 ГБ в покое и до 5,5 ГБ, когда идёт подготовка видео или сборка.

| Что | Значение |
| --- | --- |
| Свежий контейнер в покое | ≈190 МБ памяти |
| Контейнер с открытым интерфейсом и выполненным запросом | ≈480 МБ |
| Загрузка процессора в покое | 0,1–0,4 % ядра |
| Запуск среды при первом входе | ≈3 секунды до готовности сервера (образ уже на диске) |
| Пробуждение остановленной среды | ≈3 секунды, файлы на месте |
| Образ | 1,33 ГБ (общий слой) |

**Вывод по текущему серверу.** Запас по памяти 3–5 ГБ при бюджете ≈0,6 ГБ на активного пользователя: безопасно **3 одновременные среды**, с риском 4.
Это годится для закрытого теста и ранней беты, но не для открытого запуска: сервер общий, и пик подготовки видео может съесть память.

**Оценка для отдельного сервера (допущения, проверить на нагрузке).** 16 ГБ и 8 vCPU: резерв 4 ГБ системе, остальное — среды по ≈0,8–1 ГБ в пике, то есть **10–12 одновременных сред**.
Если активно одновременно 8–12 % зарегистрированных, это ≈100–150 пользователей на сервер. Процессор не узкое место: агент большую часть времени ждёт ответ нейросети.
Диск: мягкий предел 5 ГБ на человека, 200 ГБ хватает на ≈40 человек с полностью занятыми квотами (реально занято много меньше).

## Что осталось до открытого доступа

1. **Квоты и учёт.** Диск (проверка размера томов, предупреждение и блокировка), часы работы в сутки на человека, учёт в базе менеджера уже ведётся (`usage`).
2. **Вход с сайта.** Выложить `code-cloud.php`, конфиг `.config/cloud.php` (секрет общий с менеджером), кнопку «Открыть в облаке» на `code.php` для допущенных.
3. **Домен.** `cloud.codary.ru` вместо sslip.io: нужна A-запись на 159.195.232.233 (или на новый сервер), затем сертификат.
4. **Усиление изоляции для публики.** Контейнеры делят ядро с хостом: для посторонних пользователей нужен gVisor (`runsc`) или Kata, плюс ограничение исходящего трафика
   на человека и сигнал о подозрительной нагрузке (майнинг, сканирование).
5. **Ключи пользователей.** Лежат в томе открытым текстом, как и в настольном приложении. Для платной версии разумно шифровать том и не доверять хранение
   ключей слабым местам (минимум: ограничить доступ к томам, шифрование диска сервера).
6. **Резервные копии** томов и восстановление; мониторинг и оповещения администратору (память, число сред, ошибки запуска).
7. **Отдельный сервер**, когда пойдёт открытая бета.
8. **Правовое.** Облако хранит код и данные пользователей на сервере в Германии: нужны разделы в оферте и политике (что хранится, где, срок, удаление), согласие на
   трансграничную передачу. Те же вопросы про шлюз, пока закрытый режим не снят.
9. **Шлюз Codary как провайдер по умолчанию** в облаке — только после открытия шлюза (см. флаг `gatewayProvider`).

## Этапы

* **0. Прототип (сделано).** Менеджер, nginx, образ, правила сети, тесты (`cloud/tests/smoke.py`, 16 проверок, все проходят).
* **1. Закрытая альфа.** Вход с сайта, список допущенных, квоты и учёт, домен, мониторинг. Нагрузка — на нынешнем сервере, 3 среды.
* **2. Бета.** Отдельный сервер, усиленная изоляция (gVisor), резервные копии, правовые тексты, платный или лимитированный доступ.
* **3. Развитие.** Задачи по расписанию и Telegram, которые работают круглосуточно (в облаке среда может не засыпать, пока есть задачи); общие рабочие пространства.
